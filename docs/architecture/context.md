# 시스템 맥락

## 문서 목적

시스템이 해결하는 문제와 책임 경계, 주요 사용자와 외부 시스템을 설명합니다. 상세 인터페이스 계약은 다루지 않습니다.

## 언제 수정하는가

- 시스템의 책임 범위 또는 주요 사용자가 달라질 때
- 새로운 외부 시스템을 연동하거나 기존 연동을 제거할 때
- 외부와 주고받는 정보의 목적이 바뀔 때

## 해결하는 문제

추론 작업 요청을 동기 응답으로 처리하면 처리 지연이 곧바로 API 응답 지연과 타임아웃으로 이어집니다. 이 시스템은 요청 접수와 실제 처리를 분리하고, 병목이 발생한 구간을 관측 지표로 식별해 그 구간만 분리·확장할 수 있는 구조를 제공합니다.

책임 범위는 작업 접수, 상태 관리, 비동기 처리 파이프라인, 실패 격리와 재처리, 그리고 이 모든 과정의 관측입니다.

## 대상과 관계

| 대상 | 관계 | 주고받는 정보 |
|---|---|---|
| API 클라이언트 | 작업 생성과 상태 조회 | 요청 payload, `job_id`, 처리 상태와 결과 |
| 운영자 | 상태 관측과 장애 대응 | 지표, 로그, 트레이스, 경보 |
| Kafka | 작업 이벤트 전달 | 이벤트 Envelope |
| PostgreSQL | 작업 상태와 이벤트 이력의 기준 저장소 | `jobs`, `job_events` |
| Redis | 멱등성 예약과 처리 잠금 | 멱등성 키와 상태 |
| 관측 스택 | 지표·로그·트레이스 수집 | Prometheus 지표, 컨테이너 로그, OTLP 스팬 |

정식 시각화는 [C4 System Context](diagrams/c4/context.md)에 있으며, 이 문서에는 관계의 의미를 기록합니다.

## 범위 밖 항목

- 실제 GPU 추론 모델의 학습과 서빙. 현재는 [GPU 추론 시뮬레이터](../decisions/ADR-0006-gpu-inference-simulator.md)로 처리 특성만 재현합니다.
- 인증과 권한. 현재 API는 인증을 요구하지 않으며, 신뢰 경계 안에서 호출된다고 가정합니다.
- 멀티테넌시, 사용량 제한, 과금.
- 결과물의 장기 보관과 외부 전달(Object Storage, 알림 등). downstream 처리는 현재 더미 구현입니다.
